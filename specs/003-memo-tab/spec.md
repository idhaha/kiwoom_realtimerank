# Feature Specification: 메모 탭 — 캘린더 및 리치 텍스트 메모

**Feature Branch**: `003-memo-tab`

**Created**: 2026-09-29

**Status**: Draft

**Input**: 기존 구현(브라운필드) 문서화 — 현재 구현과 이 Feature의 Spec Kit 산출물을 기준으로 정리

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 리치 텍스트 메모 작성 및 저장 (Priority: P1)

사용자는 Quill 에디터로 서식 있는 투자 메모(트레이딩 일지 등)를 작성하고, 명시적으로 저장 버튼을 눌러 브라우저와 서버 양쪽에 영구 저장할 수 있다.

**Why this priority**: 메모 탭의 핵심 목적이며, 캘린더 연동 없이도 독립적으로 가치를 제공한다.

**Independent Test**: 메모를 작성하고 저장 버튼을 클릭한 뒤 페이지를 새로고침해도 내용이 유지되는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 메모를 작성한 상태, **When** [저장] 버튼을 클릭하면, **Then** 내용이 브라우저 로컬과 서버 양쪽에 저장되고 저장 완료 메시지가 잠시 표시된다.
2. **Given** 다른 PC에서 저장한 최신 메모가 서버에 있는 상태, **When** 사용자가 [새로고침] 버튼을 클릭하면, **Then** 페이지 전체를 새로고침하지 않고 에디터 내용만 서버 최신값으로 갱신된다.
3. **Given** 사용자가 툴바의 [Today] 버튼을 클릭한 상태, **When** 클릭이 발생하면, **Then** 현재 시각 문자열이 커서 위치에 굵은 글씨로 삽입된다.

---

### User Story 2 - Google 캘린더 일정 관리 (Priority: P2)

사용자는 Google 계정으로 인증한 뒤, 개인 일정을 월간 캘린더에서 등록·수정·삭제하고 대한민국 공휴일을 함께 확인할 수 있다.

**Why this priority**: 메모 작성과는 독립적인 기능으로, 인증이 필요해 P1보다 진입장벽이 있다.

**Independent Test**: 빈 날짜를 클릭해 일정을 등록하고, 캘린더에 즉시 반영되는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 Google 인증을 완료한 상태, **When** 빈 날짜를 클릭해 일정을 등록하면, **Then** 새 일정이 캘린더에 즉시 표시된다.
2. **Given** 공휴일 일정이 표시된 상태, **When** 사용자가 해당 일정을 클릭하면, **Then** 수정/삭제 옵션 없이 읽기 전용으로 표시된다.
3. **Given** Google 인증 토큰이 만료된 상태, **When** API 요청이 401을 반환하면, **Then** 시스템은 토큰을 초기화하고 재인증을 시도한다.

### Edge Cases

- 메모 탭이 숨겨진(`display: none`) 상태에서 처음 초기화되면 어떻게 되는가? → 탭이 실제로 활성화되는 시점까지 초기화를 미룬다.
- 서버 통신이 실패한 상태에서 저장을 시도하면 어떻게 되는가? → 브라우저 로컬 저장소에는 우선 보존되어 작성 내용이 유실되지 않는다.
- 타이핑 중 자동 저장이 발생하는가? → 발생하지 않는다. 명시적 저장 버튼 클릭 시에만 저장된다(다중 PC 레이스 컨디션 방지).

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 리치 텍스트 편집 기능(제목, 굵게/기울임/밑줄/취소선, 목록, 색상, 인용구, 코드블록, 링크, 이미지)을 제공해야 한다.
- **FR-002**: 시스템은 [Today] 버튼으로 현재 일시 문자열을 커서 위치에 굵게 삽입해야 한다.
- **FR-003**: 메모는 HTML과 서식 복원용 구조화 데이터(Delta) 두 형태로 동시 저장되어야 한다.
- **FR-004**: 메모 저장은 사용자가 명시적으로 [저장] 버튼을 클릭할 때만 발생해야 하며, 타이핑 중 자동 저장되어서는 안 된다.
- **FR-005**: [새로고침] 버튼은 전체 페이지를 새로고침하지 않고 서버의 최신 메모로 에디터만 갱신해야 한다.
- **FR-006**: 서버 통신 실패 시에도 작성 중인 메모는 브라우저 로컬 저장소에 보존되어야 한다.
- **FR-007**: 시스템은 사용자의 기본 캘린더와 대한민국 공휴일 캘린더를 함께 조회해 표시해야 한다.
- **FR-008**: 공휴일 일정은 시각적으로 구분되며 수정·삭제할 수 없어야 한다.
- **FR-009**: 사용자는 빈 날짜를 클릭해 새 일정을 등록하고, 기존 일정을 클릭해 수정·삭제할 수 있어야 한다.
- **FR-010**: Google 인증은 앱 초기 구동 시 자동으로 요구되지 않고, 사용자가 동기화나 캘린더 조작을 시도할 때만 요청되어야 한다.
- **FR-011**: 인증 토큰이 만료(401)되면 시스템은 이를 감지해 자동으로 재인증을 시도해야 한다.
- **FR-012**: 메모 탭이 화면에 보이지 않는 상태에서는 에디터/캘린더 초기화를 지연해야 한다.

### Key Entities

- **메모(Memo)**: HTML 콘텐츠, Delta(구조화 서식), 최종 저장 시각을 가진다.
- **캘린더 일정(Event)**: 제목, 시작/종료 일시, 종일 여부, 설명을 가진다.
- **공휴일 이벤트(Holiday Event)**: 제목, 날짜를 가지며 읽기 전용이다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자가 [저장]을 클릭한 후 3초 이내에 저장 완료 피드백을 확인할 수 있다.
- **SC-002**: 네트워크 단절 상황에서도 작성 중이던 메모 내용의 손실률은 0%다.
- **SC-003**: 새로고침 버튼 사용 시 전체 페이지 리로드 없이 5초 이내에 최신 메모가 반영된다.

## Assumptions

- 사용자는 개인 Google 계정을 보유하고 있으며, 캘린더 연동은 선택 사항으로 간주한다.
- 공휴일 캘린더는 대한민국 기준으로 고정하며, 다국가 지원은 이 기능 범위 밖이다.
- 브라운필드 문서화로, 현재 `br_oracle` 브랜치의 동작을 기준으로 작성했다.
