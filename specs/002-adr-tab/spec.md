# Feature Specification: ADR 탭 — 등락비율 듀얼 차트

**Feature Branch**: `002-adr-tab`

**Created**: 2026-09-29

**Status**: Draft

**Input**: 기존 구현(브라운필드) 문서화 — 현재 구현과 `GET /api/adr` 프록시 계약을 기준으로 정리

## User Scenarios & Testing *(mandatory)*

### User Story 1 - KOSPI/KOSDAQ ADR 듀얼 차트 비교 (Priority: P1)

사용자는 ADR 탭에서 KOSPI와 KOSDAQ의 등락비율(ADR) 시계열을 두 개의 차트로 나란히 비교하며, 시장 과열/침체 여부를 시각적으로 판단할 수 있다.

**Why this priority**: ADR 탭의 존재 이유 자체이며, 이것만으로도 독립적인 가치를 제공한다.

**Independent Test**: ADR 탭을 열었을 때 두 차트에 각각 시계열 데이터가 그려지고, 80/100/120 기준선이 표시되는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 사용자가 ADR 탭을 연 상태, **When** 데이터 로드가 완료되면, **Then** KOSPI·KOSDAQ 차트에 각각 시계열 라인과 80(주황)/100(빨강)/120(초록) 기준선, 80~120 정상 구간 음영이 표시된다.
2. **Given** 원천 사이트 응답이 비정상(짧거나 빈 배열)인 상태, **When** 조회가 실패하면, **Then** 기존 차트 렌더링은 유지된 채 상태 텍스트가 "업데이트 실패"로 바뀐다.

---

### User Story 2 - 조회 기간 전환 (Priority: P2)

사용자는 6개월/1년/2년/5년/10년 중 원하는 기간을 선택해 차트에 표시되는 거래일 수를 즉시 바꿀 수 있다.

**Why this priority**: 분석 관점(단기/장기 추세)을 바꾸는 보조 기능으로, P1 없이는 의미가 없다.

**Independent Test**: 기간 버튼을 클릭했을 때 표시 거래일 수가 바뀌고 최신 데이터가 화면 우측 끝에 오는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 기본 기간(2년)이 표시된 상태, **When** 사용자가 "10y" 버튼을 클릭하면, **Then** 차트가 2400 거래일 범위로 전환되고 최신 데이터가 우측 끝에 위치한다.

---

### User Story 3 - 두 차트 커서·줌 동기화 (Priority: P3)

사용자는 한쪽 차트에서 마우스를 움직이거나 확대/이동할 때 반대편 차트도 동일하게 반응하는 것을 보며 두 시장을 정밀 비교할 수 있다.

**Why this priority**: 분석 편의를 높이는 향상 기능으로, 동기화 없이도 각 차트는 독립적으로 유효하다.

**Independent Test**: KOSPI 차트에서 마우스를 호버했을 때 KOSDAQ 차트에도 동일 일자의 십자선이 나타나는지 확인해 검증할 수 있다.

**Acceptance Scenarios**:

1. **Given** 두 차트가 모두 렌더링된 상태, **When** 사용자가 한 차트를 드래그(패닝)하면, **Then** 반대편 차트도 동일한 시작 날짜(날짜 기준 가장 가까운 거래일)와 동일한 표시 거래일 수로 이동한다.

### Edge Cases

- KOSPI와 KOSDAQ의 데이터 개수가 다르면(휴장일 등) 어떻게 되는가? → 콘솔에 경고를 기록한다. 데이터를 자르지는 않으며, 각 차트는 자기 데이터 길이를 넘지 않도록 표시 거래일 수와 스크롤 위치를 제한한다. 차트 간 동기화는 날짜 기준 가장 가까운 거래일로 매핑한다.
- 원천 HTML 파싱(JSON.parse)이 실패하면 어떻게 되는가? → 정규식 기반 2차 파싱을 시도한다.
- ADR 탭이 비활성 상태에서 자동 갱신 타이머가 돌면 어떻게 되는가? → 캔버스 재렌더링을 지연시키고, 탭이 다시 활성화될 때 1회만 전체 렌더링한다.

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 시스템은 KOSPI·KOSDAQ 각각의 ADR 시계열을 서버 프록시(`GET /api/adr`)를 통해 조회해야 한다.
- **FR-002**: 시스템은 두 시장의 Y축 스케일을 공유(공통 최소/최대값)하여 동일 기준으로 비교 가능하게 해야 한다.
- **FR-003**: 시스템은 80/100/120 기준선과 80~120 정상 구간 음영을 표시해야 한다.
- **FR-004**: 시스템은 사용자가 6개월/1년/2년/5년/10년 중 조회 기간을 선택할 수 있게 해야 하며, 기본값은 2년이다. 각 기간은 6개월=120, 1년=240, 2년=480, 5년=1200, 10년=2400 거래일에 대응한다.
- **FR-005**: 시스템은 한 차트의 호버·패닝·줌 조작을 반대편 차트에 실시간으로 동기화해야 한다. 줌은 마우스 휠로 조작하며 포인터 위치를 기준으로 확대/축소되고, 최소 30 거래일까지 확대된다(상한은 해당 시장 데이터 길이).
- **FR-006**: 원천 응답이 비정상이면 시스템은 기존에 렌더링된 내용을 유지하고 실패 상태만 표시해야 한다. 응답 오류(HTTP 비정상), 응답 본문 100자 미만, 파싱 결과에서 KOSPI·KOSDAQ 중 한쪽이라도 데이터가 0건인 경우를 모두 비정상으로 본다.
- **FR-007**: 시장별 데이터 길이가 다르면 시스템은 각 차트의 표시 거래일 수와 스크롤 위치를 자기 데이터 길이 안으로 제한하고, 차트 간 동기화는 날짜 기준 가장 가까운 거래일로 매핑하여 범위 밖 접근 없이 안전하게 처리해야 한다.
- **FR-008**: 시세 지표 갱신 자체(수동 조회·자동 갱신 타이머)는 사용자 설정 저장을 트리거해서는 안 된다. 단, 사용자가 자동 갱신 간격 선택값을 바꾸는 조작은 설정 변경이므로 저장을 트리거한다(006-settings-sync 범위).
- **FR-009**: 탭이 비활성 상태일 때 시스템은 불필요한 캔버스 재렌더링을 지연시켜야 한다.

- **FR-010**: 시스템은 ADR 탭 헤더에 '조회' 버튼과 자동 갱신 간격 선택(30초/1분/10분/1시간)을 제공하고, 마지막 갱신 시각과 상태 텍스트(대기 중.../데이터 로딩 중.../업데이트 완료/업데이트 실패)를 표시해야 한다. 저장된 간격이 없으면 기본값은 10분이다. 과거에 제공되던 '당일누적' 옵션은 제거되었으며, 이전에 이 값이 저장되어 있으면 30초 간격으로 대체한다.

- **FR-011**: 시스템은 각 차트 상단에 최신 값(호버 중이면 호버한 날짜의 값)과 날짜를 표시하고, 값이 120 이상이면 초록, 100 이상이면 하늘색, 80 이상이면 주황, 80 미만이면 빨강으로 구분해야 한다.

### Key Entities

- **ADR 데이터 포인트**: 날짜, 값(등락비율 %)을 가진다.
- **시장(Market)**: KOSPI 또는 KOSDAQ 구분을 가진다.

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 사용자는 ADR 탭 진입 후 정상 상황에서 8초 이내에 두 차트의 초기 데이터를 확인할 수 있다.
- **SC-002**: 기간 버튼 클릭 시 1초 이내에 화면이 새 기간으로 전환된다.
- **SC-003**: 원천 사이트 응답 이상 시에도 화면이 비어 보이는 경우가 0%다(직전 데이터 유지).

## Assumptions

- 브라운필드 기능 문서화이며, 원천 사이트(adrinfo.kr)의 HTML 구조가 사양서 작성 시점과 동일하게 유지된다고 가정한다.
- 단일 사용자 환경으로, 다중 사용자 동시 접근에 따른 성능 요구사항은 별도로 정의하지 않는다.
- 두 차트의 공유 Y축 범위(FR-002)는 두 시장의 데이터 길이가 같을 때 완전히 동일하다. 길이가 다르면 각 차트의 표시 구간 기준으로 계산되어 미세하게 다를 수 있다(코드 읽기 기준이며 브라우저에서 별도 검증하지 않음).
